# v0.7.0 公开测试安全基线

## 保护结构

1. Nginx 控制请求频率和请求体大小，生成提交按 IP 平均每分钟 60 次、允许短时 burst 30；健康检查、埋点、下载和普通 API 使用独立且更宽松的策略。
2. FastAPI 使用服务端签名匿名 Cookie 作为授权身份，按匿名用户执行 5 分钟、小时和每日额度。前端提交的匿名 ID 只保留兼容性，不参与授权。
3. Redis 保存限流计数、任务状态、5 个并发租约、15 个排队位置和每日成本，不保存完整经历或简历正文。
4. 模型层统计调用、Token 和估算成本，达到 50%/80% 记录分级告警，达到 100% 停止新模型调用。

校园共享网络以匿名身份为主、IP 为异常保险：默认同 IP 5 分钟 60 次、每小时 300 次、每天 1,000 次。短时间出现大量身份或相同输入跨身份重复时只记录观察事件，为后续验证码提供依据，不在 v0.7.0 对正常校园用户强制挑战。

## 1. Redis

Ubuntu/Debian：

```bash
sudo apt update
sudo apt install -y redis-server
sudo systemctl enable --now redis-server
redis-cli ping
```

期望输出 `PONG`。Redis 只监听本机，不要把 6379 端口暴露到公网。

## 2. 生产环境变量

```bash
sudo install -d -m 700 /etc/resume-coach
sudo cp /www/wwwroot/resume-coach-app/.env.example /etc/resume-coach/resume-coach.env
sudo chmod 600 /etc/resume-coach/resume-coach.env
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
```

将三次随机值分别写入 `ANONYMOUS_COOKIE_SECRET`、`DOWNLOAD_SIGNING_SECRET` 和 `IP_HASH_SECRET`。生产配置至少确认：

```dotenv
APP_ENV=production
ALLOWED_ORIGINS=https://你的域名
ALLOWED_HOSTS=你的域名,127.0.0.1
REDIS_URL=redis://127.0.0.1:6379/0
RATE_LIMIT_DRY_RUN=true
MAX_CONCURRENT_GENERATIONS=5
MODEL_MAX_CONCURRENT_CALLS=5
MAX_GENERATION_QUEUE_SIZE=15
MAX_RAW_INPUT_CHARS_SOFT=2000
MAX_RAW_INPUT_CHARS=4000
MAX_REQUEST_BODY_BYTES=131072
LLM_TIMEOUT_SECONDS=75
MAX_LLM_CALLS_PER_ATTEMPT=2
```

若模型供应商允许的并发低于 5，将 `MODEL_MAX_CONCURRENT_CALLS` 调低。填写实际模型单价后，成本熔断才具备可信的金额口径。开发、测试和生产使用不同 API Key。

## 3. systemd

```bash
cd /www/wwwroot/resume-coach-app
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
sudo cp docs/systemd-v070-example.service /etc/systemd/system/resume-coach-backend.service
sudo install -d -o www-data -g www-data backend/data backend/logs backend/outputs backend/reports
sudo chown -R www-data:www-data backend/data backend/logs backend/outputs backend/reports
sudo systemctl daemon-reload
sudo systemctl enable --now resume-coach-backend
sudo systemctl status resume-coach-backend --no-pager
```

示例使用一个 Uvicorn 进程和内部任务线程池；Redis 负责全站并发和队列原子状态。不要在未重新评估 SQLite 写入竞争和模型并发前随意增加 worker。

## 4. Nginx

先替换示例中的域名和证书路径，再合并到站点配置。确保 `limit_req_zone` 位于 `http {}` 层级。

```bash
sudo nginx -t
sudo systemctl reload nginx
```

使用 CDN 时只信任供应商公布的回源 IP 段，不要无条件信任公网传入的 `X-Forwarded-For`。删除重复 `server_name`，避免 Nginx 忽略其中一个站点块。

## 5. 验证与观察

```bash
curl -fsS http://127.0.0.1:8001/api/health/live
curl -fsS http://127.0.0.1:8001/api/health/ready
python scripts/export_runtime_protection.py --days 1
```

`ready` 必须同时通过数据库、Redis、磁盘和生产密钥检查。前 3 天保持 `RATE_LIMIT_DRY_RUN=true`，每日检查：正常用户预计限流比例、共享 IP、生成成功率、P90 排队时间、Token 和成本。确认阈值后改为 `false` 并重启后端。

可以使用 root 的 crontab 每天导出报告并触发过期轮转日志清理：

```cron
15 2 * * * cd /www/wwwroot/resume-coach-app && .venv/bin/python scripts/export_runtime_protection.py --days 1 >> /var/log/resume-coach-report.log 2>&1
```

Redis 短时异常时服务进入单进程 1 并发保守模式；生产环境持续异常超过 `REDIS_DEGRADED_MAX_SECONDS` 后暂停新生成。已有结果查看和签名 DOCX 下载不依赖新模型调用，仍尽量保持可用。
