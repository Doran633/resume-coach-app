# v0.5 质量可观测性

质量日志默认位于 `backend/logs`。日志用于发现模型、Prompt 或后处理链路退化，不应保存完整用户输入、完整推荐版本或完整简历正文。

| 日志 | 观察内容 | 何时查看 | 修改正文 |
|---|---|---|---:|
| `resume_section_fallback.jsonl` | 结构补全、来源字段、触发阶段 | DOCX 空白或触发率升高 | 是 |
| `experience_boundary.jsonl` | ID 绑定、跨经历污染修复 | 多经历发生技术或指标串用 | 是 |
| `fact_coverage.jsonl` | 明确事实、高价值事实覆盖和恢复 | 输入丰富但输出变短 | 是 |
| `resume_fact_dedup.jsonl` | 完全、包含和语义重复决策 | 重复反弹或事实被误删 | 是 |
| `resume_dedup_quality.jsonl` | 去重后 provenance 与覆盖质量 | Dedup Precision / Recall 异常 | 是 |
| `resume_summary_quality.jsonl` | 教练话术、无支撑优势和事实来源 | 个人优势空泛或过长 | 是 |
| `resume_skill_evidence.jsonl` | 技能证据、待学习技能清理 | 技能幻觉或技能被误删 | 是 |

## 异常信号

- Resume Section Fallback 触发率持续高于 20%：检查模型结构化输出、Prompt 和 JSON 修复，不要继续让 fallback 静默兜底。
- `source_experience_id` 绑定率低于 90%：检查语义分段、Experience Identity 和 reconciliation。
- 高价值事实覆盖率低于 80%：检查生成压缩、详情预算、去重和事实恢复顺序。
- 跨经历污染修复数量突然升高：检查模型或 Prompt 是否开始忽略 Experience ID。
- DOCX 投递修复率超过 10%：检查保存结果是否已经发生结构或污染退化。
- 去重删除率异常升高：检查 Precision，确认独立工程事实没有因技术词相同被误删。
- Output Firewall、Role 或 Text Integrity 修复量持续升高：定位首个污染阶段，不要把最终防线当成长期清洁工具。

## 使用原则

- Fallback 是安全网，不是垃圾桶。
- 用户可以无感恢复，开发者必须看见恢复发生过。
- Guard 修复量异常时，应定位上游首次产生问题的阶段。
- 日志失败不得影响用户生成，但发布检查必须验证关键日志可写。
- 聚合报告只输出计数、比例、阶段和内部 ID，不输出用户原文。
