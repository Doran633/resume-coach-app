- 修改前：Canonical 引用协议已经要求每个 eligible Fact 精确一次，但两份实际发送任务仍带项目恢复、详情重写、层次补齐及表头赋值要求。

- 内部协议、拒绝条件、eligible Fact 集合、文本、source span、Claim lineage、Build/Views 均未变。允许空 intro/role 和同 owner 不重叠的多 Fact 组合，重复仍拒绝，不删除后一次引用，不跨响应搬引用。
- 独立 legacy 保留原项目写作能力。两份完整 legacy 模板按空白归一化后的 SHA256 与修改前完全一致，另执行实际 legacy 接收对照；这不意味着真实模型文案逐字稳定。

## 真实模型验收计划与停止条件

- 固定输入使用本次完整课程双项目和已有准确输入；另外保留未参与调试的真实多经历及自然长输入。冻结输入、目标岗位、模式、包装级别与运行版本；仅改变其中一项时另分组记录。
- 建议选三份固定输入、两份保留输入，每份独立生成三次，共十五个请求；执行前由用户确认模型费用。首次/第二次模型尝试分别按现有 attempt/request 日志关联，统计首轮成功、重试成功、最终失败与每种拒绝原因；不能只报最终成功总数。
- 同时核对实际初始正文的完整限定、owner 与字段来源，保存和 DOCX 的首次差异归到对应后续模块。页面“生成成功”或单次 smoke 不能替代事实归属与唯一引用验收。
- 若既有记录不含原始引用数组，只能确定拒绝原因与计数，不能推断跨字段还是行内重复。不能为补历史证据反推 DOCX 或新增敏感日志。
- 本次只能证明竞争任务退出及既有协议未放宽，不能保证真实模型不再重复。若固定/保留样本仍反复重复，停止发布验收，提交同版本的计数与可取得的引用结构证据，另行审批协议简化；不在本补丁自动去重、删选、加调用或转 Fallback。
