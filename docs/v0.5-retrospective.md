# v0.5 阶段复盘

## 阶段目标

v0.5.x 的目标不是继续增加简历内容，而是让已有事实以更专业、更有逻辑、更少重复的方式进入正式简历。系统从“事实存在且边界正确”推进到“事实组织合理、每句话有信息增量、招聘者可以快速理解”。

## 主要问题与解决方式

- **重复事实**：从文本相似度升级为事实簇、来源事实 ID、包含关系和信息量联合判断，在删除重复的同时保护独立工程侧面。
- **句子断裂**：恢复语义单元，保持指标与优化对象、动作与结果位于同一完整句中。
- **异常符号与空格**：拆分配对符号、语义空格和排版字符职责，保护技术词、版本号和数字单位。
- **技能分类退化**：先验证技能证据，再按招聘者常见分类组织，禁止从知识补齐清单反向写入待学习技能。
- **职责占位污染**：以当前 `experience_id` 的职责事实恢复 role，无法恢复时允许不渲染，不写系统占位说明。
- **个人优势过度展开**：收敛为 1-2 条候选人定位，用最强能力组合建立第一印象，项目和实习负责证明。
- **内部字段暴露**：将实现字段和 Pipeline 名称转换为事实边界、结构完整性和质量治理等招聘者可理解的工程价值。

## Dedup Precision 与 Recall

去重过弱会让同一事实在 intro、role 和 details 中反复出现；去重过强会吞掉 Citation、评测、部署、隔离等使用相似技术词但价值不同的事实。v0.5 使用 provenance、事实动作、对象、指标和工程价值共同判断，只删除没有新增信息的表达。

每个项目不采用统一模板。项目、实习、科研和竞赛拥有不同事实结构，系统只要求叙事连贯和信息递进，不要求机械覆盖“背景、职责、技术、结果”全部槽位。事实不足时宁可少写，也不补模板句。

## 黄金回归

黄金回归不比较全文，因为句式变化和专业化改写本身是产品能力。它固定以下不变量：经历数量、事实覆盖、经历边界、类型、技能分类、重复数量、内部字段和 DOCX 投递质量。真实模型质量评测单独运行，模型波动不会让普通 CI 随机失败。

## 当前技术债务

- 生成与 DOCX 管线仍然较长，多个必要复检点增加了理解成本。
- 部分服务同时承担修复和日志职责，未来可进一步明确只读检测器与写入者。
- 黄金案例数量较少，需要根据匿名真实失败案例逐步增加，而不是人为堆造样例。
- 真实模型质量评测尚未形成长期趋势图，需要依靠报告做版本间比较。
- 前端主包仍有体积告警，移动端和生成等待体验仍有提升空间。

## v0.6.0 边界

v0.6.0 优先优化生成等待状态、错误重试、结果到导出的操作路径、移动端结果导航、首次用户引导和前端代码分包。默认不修改 Experience ID、Fact Ledger、Fact Coverage、Dedup、Summary Quality、Skill Evidence 和 DOCX 正文规则；只有黄金回归或真实失败案例证明质量退化时才进入生成链路。

## 可用于项目复盘的总结

围绕真实用户简历生成场景，构建基于 Experience ID 与 Fact Ledger 的结构化质量管线，通过事实覆盖、经历边界、事实簇去重、技能证据校验和 DOCX 投递检查解决多经历串用、重复事实、内部字段泄露与结构退化问题；进一步建立匿名黄金案例和确定性回归，将生成质量从人工抽查升级为可验证、可观测的工程基线。
