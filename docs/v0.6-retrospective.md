# v0.6.x 阶段复盘

## 阶段目标

v0.6.x 没有改变 Resume Coach 的核心产品方向，而是把真实内测中最影响专业性的失败形态逐步收敛为可验证的不变量：同一经历只出现一次，技能必须有证据，正式项目必须有效，生成尝试能够被追踪，最终页面和 DOCX 必须通过统一投递检查。

## 真实问题与解决路径

- 同一项目被口语重复提及后生成两次：引入经历实体级去重，按 `source_experience_id`、规范标题和局部事实指纹判断实体唯一性。
- 父产品与 MVP、阶段或模块重复输出：引入项目层级关系，使用父子证据合并，而不是降低普通相似度阈值。
- “Token 消耗”被误写成安全机制：引入技术术语上下文消歧，要求技能分类绑定 `experience_id` / `fact_id` 证据。
- “其他经历”与标题残片进入 DOCX：在分段、Fallback 和最终有效性检查三处建立事实准入门槛。
- 内测请求与成功结果无法准确对应：使用匿名 `attempt_id` 串联提交、等待、成功、失败和导出事件，并移除埋点中的完整经历。
- 多个局部 Guard 难以保证最终状态：新增最终投递质量门，在保存与导出前统一复检现有结果。

## 为什么不能只靠 Fallback

Fallback 只能在上游不可用时恢复最低可用结构，不能证明内容归属、事实覆盖或文本专业性。若让它为每个内部 ID 强行补项目，标题残片和低质量分段会被放大为正式经历。v0.6.x 将 Fallback 限制为“有独立事实才可创建”，并保证最终质量门之后不再调用 Fallback。

## Precision 与 Recall

输出质量不能只追求删除。过低 Precision 会误删两个技术相似但真实独立的项目，过低 Recall 又会放过空壳、重复和跨经历污染。当前策略是：完全重复、标题空壳、内部字段和明确跨经历事实高置信修复；语义相似但事实 ID、指标、动作或结果不同的内容保留；低置信问题只进入日志。

## 最终质量门

最终质量门不创造新能力，而是编排已有的 Fact Guard、Experience Boundary、Experience Validity、Skill Evidence、Text Integrity、Typography 和 Output Firewall。修复遵循同段事实恢复、确定性文本修复、安全删除的顺序，并比较修复前后的高价值事实覆盖率。质量门要求幂等，重复执行不能继续改变结果。

## 当前技术债务

- 真实模型的语义波动仍需要离线评测集持续观察，确定性后处理不能替代模型质量。
- 低置信跨经历语义和近义重复仍以日志观察为主，后续可引入更稳定的离线语义评估，而不直接阻断用户生成。
- 服务数量较多，新增正文写入者时必须更新管线文档并证明其位于正确的复检之前。
- 当前 SQLite 适合小规模内测；推广前仍需补充备份、迁移演练、访问控制与并发容量评估。

## 下一阶段建议

v0.7.x 应优先建设可量化的真实模型评测和用户体验优化：扩充匿名黄金案例，按岗位和经历类型比较事实覆盖、边界准确率、重复率与人工偏好；同时继续优化等待反馈、失败重试和结果解释。不要以新增更多 Guard 代替模型、Prompt 和评测体系的改进。

## 项目复盘表达

围绕多经历简历生成中的事实串用、实体重复、术语歧义和空壳输出问题，设计 Experience ID、Fact Ledger、实体层级识别、上下文消歧与最终投递质量门；通过高价值事实覆盖率和脱敏结构化日志平衡问题拦截与内容完整性，并以黄金样例和真实失败案例建立稳定回归基线。
