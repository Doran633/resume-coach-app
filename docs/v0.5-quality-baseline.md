# v0.5 质量基线

## 基线指标

v0.5.9 以匿名黄金案例 `v057_ai_agent_full_resume` 作为确定性质量基线：

| 指标 | 基线 |
|---|---:|
| 经历保留率 | 100% |
| 高价值事实覆盖率 | 不低于 90% |
| 经历边界准确率 | 100% |
| 经历类型准确率 | 100% |
| 技能分类准确率 | 100% |
| 明显重复详情 | 0 |
| 重复经历实体 | 0 |
| 内部字段泄露 | 0 |
| 个人优势 | 1-2 条 |
| DOCX 投递就绪 | 是 |

该基线通过固定 `GenerationPayload` 运行确定性后处理和生产 DOCX 链路，不依赖模型、网络或 API 配额。真实模型评测单独运行，不作为普通 `pytest` 的强制门禁。

## 必须守住的不变量

- 不丢失用户输入中的主要经历。
- 不跨 `experience_id` 串用技术、指标、公司、奖项、部署和实习事实。
- 不编造学校、专业、公司、实习、奖项、用户数、量化指标或技术栈。
- 高价值明确事实优先于通用包装句和篇幅压缩。
- 重复内容必须删除，每条项目详情应增加新的事实、工程侧面、证据或结果。
- 每个 `source_experience_id` 最多对应一个正式经历，归一化标题和高置信事实指纹不得重复。
- 技能必须由原始输入或经历正文提供证据，再进行分类和去重。
- 内部字段、调试文本、占位说明和求职教练话术不得进入正式简历。
- 个人优势只建立候选人定位，不复述整份简历。
- 存在真实实习时，DOCX 中实习经历位于项目经历之前。
- DOCX 不包含面试准备清单、Claim、降级表达、`experience_id` 或 `fact_id`。

## 可接受变化

- 句式、动词和专业表达发生自然变化。
- 同一事实被重新组织为更专业的简历语言。
- 项目详情顺序根据叙事逻辑调整。
- 在事实不丢失的前提下合并相似表达。
- 根据目标岗位调整事实优先级和技术侧重点。
- 在内容完整的前提下，版式在一页与两页之间合理变化。

## 不可接受退化

- 高价值事实覆盖率低于 90%，或主要经历数量减少。
- 经历类型错分、跨经历污染或硬事实幻觉。
- 重复表达、残句、异常符号、异常空格或内部字段重新出现。
- 同一经历因口语标题、Fallback 或 Reconciliation 再次生成成第二个项目。
- 技能分类错误、同一技能重复或不确定技能进入正文。
- DOCX 空白、正文截断、模块顺序错误或包含面试准备清单。
- 个人优势重新出现求职教练话术、完整技术栈或项目清单。
- 为增加篇幅而加入通用模板句，或为缩短篇幅删除独立高价值事实。

## 验证命令

```bash
python -m pytest tests/test_golden_resume_regression.py -q
python scripts/evaluate_golden_resume.py --mode mock
```

真实模型抽查需要 API 配置，会消耗 Token：

```bash
python scripts/evaluate_golden_resume.py --mode openai
```
