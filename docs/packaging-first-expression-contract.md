Applicable user-level `AGENTS.md` was read; no repository-specific `AGENTS.md` or named harness file was found. Prior real `normal_A` and `limited_A` writer responses borrowed facts not declared by their expression units; v0.9.19.3.1 still rejects those archived responses. ## Permission change

The frozen Fact/Claim text, owner, eligibility, header and necessary constraints remain unchanged. `canonical_fact_compositions_v2` still requires every eligible Fact to be explicitly referenced and meaningfully represented; a source ID alone does not prove this. It keeps contiguous owner-local source declarations, field-level lineage, bounded reuse and complete coverage by ID. Project prose may now organize those declared facts and summarize auxiliary process detail, while retaining key action, object, quantities, tools, outcomes, responsibility, team attribution, status and qualifications. No undeclared owner or Fact can support an added action or result. This version does not grant arbitrary Fact selection, noncontiguous combinations or partial overviews with missing key information.

The writer remains the only project-body writer. The independent review template assesses material conflict rather than lexical similarity. The internal review protocol is `canonical_expression_review_v4`: alongside existing `supported`, rejected and uncertain verdicts, `editorial_expansion` may approve a bounded explanatory phrase. It requires a source Fact ID, a uniquely locatable source excerpt, a uniquely locatable candidate excerpt, and five explicitly true checks for source meaning, owner scope, qualification, no new concrete action and no new hard claim. Missing, false, duplicate or malformed checks fail as invalid review. The reviewer cannot supply replacement text. A successful decision creates only a request-local receipt bound to Build fingerprint, frozen source/Claim context, position and exact candidate; subsequent material change invalidates it. Accepted editorial counts are logged without candidate text.

This is an explicitly approved **probabilistic risk assessment**, not deterministic semantic proof. The user accepted that residual risk after automatic review rejected a weaker design that would have trusted a new verdict plus two locatable excerpts alone. The final Gate still checks its existing critical issues; it is not claimed to prove all semantic assertions. The new reviewer category does not rewrite the Ledger or make inferred wording a frozen Fact.

## Controlled positive and negative cases

- A thin input's `我帮忙测试` can be professionally expressed as `在项目中协助开展测试工作` when the independent controlled review returns a complete editorial assessment. The same Fact and Claim attach to the saved detail and DOCX; the accepted category count is redacted.
- An owner-local factual sentence can receive a bounded explanatory phrase in intro, role or detail. Each field retains its own Fact/Claim lineage. A later material edit invalidates the receipt.
- Missing/false checks, foreign source IDs and excerpts absent from the precise source or candidate reject. Controlled `added_claim` and `changed_qualification` still reject invented architecture, a 50% outcome and removal of `只负责`.
- Unknown or borrowed sources still reject; normal/long first requests and corrected retries send the same frozen evidence and the new packaging boundary. A research/campus holdout input completes controlled save and DOCX without changing owner or source attachments.

The controlled reviewer returns are not evidence that the real model will classify these pairs correctly. Excerpt validity verifies localization, not semantic accuracy. A reviewer that incorrectly reports all five checks as true could still approve a bad candidate; this residual product risk must be measured in real acceptance.

## Validation and rollout boundary

Red tests initially produced 3 expected failures and 4 retained negative passes. After the structured review contract and approved test migrations, the isolated full suite passed: 1803 tests, 1892 warnings. This includes the new专项, receiver, golden and DOCX tests. Python compilation and scoped `git diff --check` passed. Existing v3 protocol assertions and normal/long task hashes were migrated only after explicit user approval; original inputs, legacy task hashes, hard-fact rejection, budget, Gate and save/DOCX assertions were retained. One initial full-suite failure came from the sandbox blocking the repository log path; the rerun redirected only test logs to an isolated GodSu directory, without mocking business logic. The pre-existing `.pytest-*` deletions make whole-worktree diff inspection noisy; they were not altered.

No paid model was called, no production database was accessed, and nothing was deployed or committed. Real-model acceptance remains required for packaging benefit, hard-claim leak rate, false rejections, truncated output, two-call budget and cost. `bold_version` is not inherently the same content as `resume_sections` or the DOCX; summary and four-version semantic quality remain separate follow-up work. This release does not change public API fields, frontend or stored revision structure.

Rollback must restore the writer's expression scope, v4 reviewer/parser/receipt signature, review template, tests and version documentation together. Retaining a v4 template with the old v3 parser would fail valid reviews; retaining v4 receipts with the old expression task would misstate the accepted permission.
