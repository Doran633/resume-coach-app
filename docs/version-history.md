# 版本历史

这份记录用于阶段性收口复盘，也可以作为后续项目展示、简历项目经历和产品迭代总结的素材。

## v0.0：核心链路起点

v0.0 完成了 Resume Coach App 的最小可运行闭环。系统支持用户输入经历，由后端生成结构化结果，前端展示包装版本、Claim 风险、面试追问和知识补齐清单，并支持生成 DOCX 文件下载。

这一阶段重点不是生成质量，而是验证产品主链路是否成立：输入经历、生成结果、查看建议、导出简历、提交反馈、记录埋点。

主要能力：

- 初始化 React + TypeScript + Vite + Ant Design 前端。
- 初始化 FastAPI + SQLite + SQLAlchemy 后端。
- 建立匿名用户、会话、事件、输入、生成结果、Claim、简历版本、生成文件和反馈表。
- 实现 mock 生成服务。
- 实现 DOCX 生成与下载。
- 实现基础埋点和反馈。

## v0.1：真实 LLM 生成链路

v0.1 将 mock 生成升级为可切换的真实 LLM 生成链路，让产品从演示原型进入可验证阶段。

主要能力：

- 支持 `LLM_MODE=mock / openai`。
- 支持 OpenAI 兼容接口配置。
- 新增 LLM 调用封装、prompt 加载、JSON 修复服务。
- LLM 返回结果校验为固定结构，避免前端字段缺失崩溃。
- Claim 风险结构扩展为证据、风险原因、面试追问、知识准备和降级表达。
- 记录 LLM 调用模式、模型、耗时、成功状态和错误信息。

## v0.1.1：数据汇总与导出

v0.1.1 增加 analytics 导出脚本，用于把线上 SQLite 数据转成可阅读、可复盘、可分享的报告。

主要能力：

- 新增 `scripts/export_analytics.py`。
- 输出 Markdown summary、events CSV、inputs CSV。
- 统计匿名用户数、会话数、事件数和关键转化率。
- 统计目标岗位、包装强度、经历类型和反馈分布。
- 汇总 LLM 调用次数、成功率、平均耗时、模型分布和错误摘要。
- 默认不导出用户原始经历，降低隐私风险。
- 报告时间统一为北京时间。

## v0.1.2：敏感信息提醒

v0.1.2 在输入页增加轻量隐私提醒，提示用户不要输入身份证号、家庭住址、银行卡号、账号密码等敏感信息。

这一版的重点是投放前的基础信任建设：提醒要明显，但不能像弹窗或强制协议一样打断体验。

## v0.1.3：结果页产品化表达

v0.1.3 优化结果页顶部介绍和项目经历展示，让页面更像求职教练工具，而不是 AI JSON 结果展示器。

主要变化：

- 顶部标题改为“先把经历写强，再告诉你怎么接住”。
- 项目经历预览使用中文标签展示。
- Prompt 增加用户可见内容中文化规则。
- 技术专有名词继续保留英文，如 RAG、React、TypeScript、FastAPI、Agent。

## v0.1.4：结果页工作台

v0.1.4 将结果页从长页面堆叠改为 Tabs 工作台。

主要能力：

- 新增定位总览、三档包装、承接检查、面试准备、简历预览五个分区。
- Claim 默认只展示强表达、风险等级和一句话建议。
- Claim 支持展开查看证据、风险原因、面试追问、知识补齐和降级表达。
- 补充信息区域独立展示，可重新生成。
- 新增 `view_result_tab`、`expand_claim`、`submit_followup` 埋点。

## v0.1.5：输入页引导优化

v0.1.5 将输入页从普通文本框升级为轻量引导式体验。

主要能力：

- 包装强度改为用户更容易理解的“基础增强 / 重点放大 / 边界测试”。
- 默认选择“重点放大”。
- 前端展示新名称，提交后端时兼容映射为旧值。
- 增加建议写法提示区。
- 增加项目、实习、开源、比赛、大模型 / Agent 五类模板。
- 模板支持一键填入或追加。
- 增加输入质量提示，不阻止提交。
- 新增包装强度、目标岗位、模板填入和质量提示相关埋点。

## v0.1.6：结果清洗与稳定性兜底

v0.1.6 在后端新增统一结果清洗层，解决 LLM 输出不稳定时用户看到内部字段、格式混乱或风险等级异常的问题。

主要能力：

- 新增 `result_cleanup_service.py`。
- 清洗所有用户可见文本字段。
- 将 `question:`、`answer_points:`、`role:`、`details:` 等内部字段替换为中文表达。
- 清理代码块、JSON 包裹、多余空格和连续换行。
- 对空字段、异常 risk level、空 claim 做温和兜底。
- 对数组和项目数量做合理裁剪。
- 写入 `backend/logs/result_cleanup.jsonl` 清洗日志。
- 保持 API schema 不变，不编造新经历。

## v0.1.7：结果阅读体验优化

v0.1.7 继续优化结果页阅读体验，重点解决定位总览和三档包装卡片文字堆叠的问题。

主要变化：

- 长版本内容拆成摘要、要点和展开详情。
- 三档包装卡片减少一屏内文字压力。
- 面试准备和补充追问的卡片化程度提升。
- 页面更接近“求职教练工作台”，而不是报告列表。

## v0.1.8：导出交付页增强

v0.1.8 调整“面试准备”和“导出与反馈”的信息分工。

主要能力：

- 结果页面试准备 Tab 聚焦面试承接和补充追问。
- 知识补齐清单移动到导出与反馈页。
- 导出页新增“面试准备清单”，作为下载简历时一起带走的交付内容。
- 面试准备清单按技术知识补齐、面试追问准备、证据材料准备、降级表达准备分组。
- 新增 `view_export_interview_plan` 埋点。

## v0.1.9：移动端适配

v0.1.9 完成移动端体验优化，为校园墙投放做准备。

主要变化：

- 移动端页面边距、卡片 padding、标题字号优化。
- 多列布局在移动端改为单列。
- Tabs 支持横向滚动。
- 输入框字体不低于 16px，避免移动端自动放大。
- 主按钮移动端更容易点击。
- 结果页、导出页、反馈页在手机上可以完成完整流程。

## v0.1.x 阶段总结

v0.1.x 已经把项目从“能生成简历建议的 demo”推进到“具备真实内测价值的求职教练 MVP”。

这一阶段形成了几个可复用的项目亮点：

- 设计并实现了结构化 LLM 工作流，将自然语言经历转为包装版本、Claim 风险、面试承接和简历内容。
- 构建了结果清洗与兜底层，提高 LLM 输出在真实产品场景中的稳定性。
- 实现了 DOCX 简历生成能力，完成从建议到文件交付的闭环。
- 建立了匿名埋点、反馈和 analytics 导出体系，为校园投放后的数据复盘做准备。
- 通过连续小版本迭代优化输入页、结果页、导出页和移动端体验。
- 在不引入登录、支付、PDF、上传简历等复杂模块的情况下，保留了产品验证所需的核心路径。

## v0.2.0：用户可见文本稳定性

v0.2.0 聚焦用户可见文本体验，解决三档包装、推荐版本、项目预览和面试准备中仍可能出现 `my_role`、`project`、`summary`、`skills` 等英文内部字段名的问题。

主要能力：

- 扩展后端结果清洗规则，覆盖 `my_role`、`project_name`、`tech_details`、`responsibilities`、`achievements` 等字段。
- 支持 `key:`、`key：`、`"key":`、`key =`、`- key:` 等多种泄露形态。
- 前端结果页增加展示前兜底清洗，避免历史数据或偶发输出污染页面。
- 三档包装卡片拆成“核心定位 / 简历表达 / 使用提醒 / 展开完整版本”，减少长文本堆叠。
- 保留 RAG、Agent、React、TypeScript、FastAPI、LangChain、LangGraph 等技术专有名词。

## v0.2.1：承接检查与完整度解释

v0.2.1 优化结果页阅读体验，让 Claim 风险不再像“系统挑刺”，而更像求职教练帮用户做强表达承接体检。

主要能力：

- 承接检查右侧风险展示从文字标签改为轻量状态圆点。
- 顶部保留可用、准备、降级、不要硬写的风险图例。
- Claim 展开详情继续保留支撑证据、风险原因、面试追问、知识补齐和降级表达。
- 信息完整度卡片增加“当前还缺什么”，基于 `missing_questions` 展示最多 3 条缺口。
- 移动端适配完整度卡片和 Claim 行布局。

## v0.2.2：DOCX 空白兜底

v0.2.2 来自真实用户测试暴露的问题：页面推荐版本有内容，但 `resume_sections.summary / skills / projects / interview_preparation` 为空，导致 DOCX 导出主体空白。

这一版的核心教训是：

> 结构合法不等于业务可用。

主要能力：

- 新增 `resume_section_fallback_service.py`。
- 在生成结果保存前补全空的 `resume_sections`。
- 在 DOCX 导出时再次兜底，支持历史空结构结果重新导出。
- 从 `recommended_version`、`bold_version`、`normal_version` 中解析个人优势、技能、项目经历和面试准备。
- 如果解析不稳定，至少生成一个“综合经历项目”，保证页面有内容时 DOCX 不空白。
- 不覆盖已有非空结构，不编造用户未提供事实。
- 新增真实用户相似 case 的 DOCX 非空回归测试。

## v0.2.3：Fallback 可观测性

v0.2.3 进一步明确：Fallback 是安全网，不应该成为垃圾桶。用户不应该感知故障，但开发者必须能感知上游 LLM 输出退化。

主要能力：

- 增强 `resume_section_fallback.jsonl` 日志结构。
- 记录 `resume_fallback_triggered`、`fallback_sections`、`fallback_reasons`、`fallback_reason`、`source_fields`、`generation_result_id` 和 `stage`。
- 区分 `generation` 和 `docx_export` 阶段 fallback。
- analytics 报告新增 Resume Fallback 监控，包括触发次数、触发率、阶段分布、section 分布、reason 分布、来源字段分布和最近摘录。
- fallback 摘录不输出用户原始输入或完整推荐版本。

## v0.2.x 阶段总结

v0.2.x 的主题是稳定性与可观测性。它没有追求继续堆功能，而是围绕真实用户使用中暴露的问题，补齐从模型输出到最终文件交付之间的工程安全层。

这一阶段形成了几个关键能力：

- 用户可见文本稳定，不再暴露内部 JSON 字段。
- 结果页风险展示更轻，完整度解释更清楚。
- DOCX 导出具备业务兜底，避免页面有内容但文件空白。
- fallback 具备可观测性，能够监控上游结构化输出退化。
- analytics 从普通埋点统计扩展到生成质量监控。

## v0.3 建议方向

v0.3 建议从“稳定可用”进入“输出质量优化”。

优先方向：

- Prompt 分层：拆分经历解析、信息缺口诊断、岗位定位、三档包装、Claim 检查、面试准备和 resume_sections 生成。
- 输出质量评分：检查结果是否具体、岗位匹配、可承接、少空泛。
- 反空泛规则：减少“提升用户体验”“负责相关工作”等无效表达。
- 岗位化生成策略：同一段经历针对 AI Agent、后端、前端、数据分析等岗位突出不同重点。
- 真实案例回归集：把真实用户 case 固化为测试样例，每次 prompt 或模型配置变更后跑回归。
- DOCX 版式优化：继续提升正式简历文件的投递质感。
